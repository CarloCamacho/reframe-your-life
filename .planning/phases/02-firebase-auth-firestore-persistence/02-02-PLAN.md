  <action>
Create `src/services/firestore.js` with the following functions:

1. **`createTree(uid, treeData)`** — Creates a new tree document at `users/{uid}/trees/{auto-id}`.
   - `treeData` should contain: `{ name, status, linkedFromTreeId, linkedFromNodeId }`
   - Auto-add `createdAt: serverTimestamp()` and `updatedAt: serverTimestamp()`
   - Use `addDoc` (auto-generate ID)
   - Return the new document reference (the caller can get `.id` from it)

2. **`updateTree(uid, treeId, updates)`** — Updates fields on an existing tree document at `users/{uid}/trees/{treeId}`.
   - Always merge `updatedAt: serverTimestamp()` into the updates
   - Use `updateDoc`

3. **`deleteTree(uid, treeId)`** — Deletes the tree document at `users/{uid}/trees/{treeId}`.
   - Use `deleteDoc`
   - Note: does NOT delete subcollection nodes (Firestore limitation) — acceptable for v1

4. **`subscribeToTrees(uid, callback)`** — Real-time listener on `users/{uid}/trees` collection.
   - Use `onSnapshot` with `query(collection(db, 'users', uid, 'trees'), orderBy('updatedAt', 'desc'))`
   - On each snapshot, map docs to objects: `{ id: doc.id, ...doc.data() }` and convert Firestore Timestamps to JS Dates for `createdAt` and `updatedAt` (use `.toDate()`)
   - Call `callback(trees)` with the mapped array
   - Return the unsubscribe function

Import from `firebase/firestore`: `collection`, `doc`, `addDoc`, `updateDoc`, `deleteDoc`, `getDocs`, `onSnapshot`, `query`, `orderBy`, `serverTimestamp`

Import `db` from `./firebase.js`

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Client -> Firestore | All CRUD goes through Firestore SDK from browser |
| Firestore Rules | Must restrict access to own UID path |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-04 | Tampering | Firestore writes | mitigate | All document paths scoped to `users/{uid}/...` — Firestore security rules must enforce `request.auth.uid == uid` (rules deployed separately, not in this plan's scope but required before production) |
| T-02-05 | Information Disclosure | Other users' trees | mitigate | Path-scoped reads: `users/{uid}/trees` only reads own data. Firestore rules enforce read restrictions |
| T-02-06 | Elevation of Privilege | Client writes arbitrary UID path | mitigate | uid parameter comes from auth state (Zustand store set by onAuthStateChanged), not from user input. Firestore rules are the server-side enforcement |
| T-02-07 | Denial of Service | Unbounded onSnapshot listeners | accept | Single user app; one listener per home screen mount. Unsubscribe returned for cleanup |
</threat_model>
